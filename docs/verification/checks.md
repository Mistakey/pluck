# 验证约定

按实际使用风险选择验证入口，不按测试数量或分支覆盖率增加用例。同一个行为尽量在一层测清楚；已经安全报错的情况，不再通过 GUI 重演。所有自动化使用独立配置目录，不读写用户的真实 Claude 或 Pluck 配置。

| 改动 | 验证 |
| --- | --- |
| 日常代码修改 | `pnpm build`（含类型检查）、`pnpm test:rust` |
| 单页界面、草稿或关闭确认 | `pnpm verify:ui`：生产构建的独立无头 Edge，受控 IPC 及真实服务读取旧版固定样本；不操作桌面 |
| 发布产物 | `pnpm tauri build` |
| 原生配置映射或 Claude CLI 升级 | `pnpm verify:cli`；检查菜单接受配置、保存实际 ID、往返后请求使用所选模型，以及真实自动审批的选定/默认/忽略覆盖路径（CLI 调试日志与本地 CPA 实收请求对应） |
| 窗口生命周期或资源开销 | Windows 下 `pnpm measure:resources --report 路径`；生产后台与隐藏窗口，无远程调试或桌面操作 |
| 窗口、托盘或交互改动 | 使用者按下述短清单人工检查，不运行模拟鼠标的 GUI 自动化 |

## 保留的自动验证

- 官方/CPA 切换、各模式最新已保存模型、菜单与别名配置、重开后读回、无关字段和凭据保持。
- CLI 或用户修改配置后，旧草稿不能覆盖新值。
- 配置写入失败不破坏原文件，CPA 连接修改涉及两个文件时保持一致。
- 文件格式保留只在服务往返中测一次；基础结构、只读与 Windows 文件占用在文件层测试。
- 网络请求成功、代表性的鉴权/连接失败与响应解析在 CPA 层验证，不在桌面和 CLI 层重复排列。

持久数据格式变更时，用变更前的固定样本验证升级；没有格式变更时不增加迁移框架或运行时兼容分支。

## 短人工检查

在隔离数据下检查：

1. 打开窗口，保存连接和模型，切换官方/CPA 后显示与保存值一致。
2. 最小化再恢复保留当前编辑；关闭再从托盘打开，读取已保存值。
3. 关闭配置窗口后托盘仍可切换模式、打开窗口，显式退出能结束后台。
4. 打开 CLI 或编辑器修改隔离配置，窗口和托盘能更新；未保存的模型草稿不被直接替换。

这部分由实际使用者观察流畅度、视觉效果与焦点行为；隐藏资源测量不替代这项人工判断。

## 资源测量边界

`measure:resources` 使用与发布版相同的 release 优化、后台和窗口工厂，独立实例及数据目录。记录初始空闲、5 次隐藏窗口创建和关闭后的整个进程树专用内存、工作集和空闲 CPU。关闭后等待 WebView 子进程回收，未回收即失败。

窗口创建用时不是可交互时间；5 次开关可发现未释放和明显累积，不能证明长期永远没有泄漏。内存应在预热后保持稳定范围，无需要求每轮字节数完全相同。不通过强制清空工作集、关闭 GPU 或后台定时重启来制造低内存数字。
